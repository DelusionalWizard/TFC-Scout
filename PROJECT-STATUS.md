## Branch forge-1.20.1: Minecraft 1.20.1, Forge 47.4.x, TFC 3.2.25, Java 17 (port by Claude Code, 7 October 2026)

This branch (git worktree `outputs/TerraFirmaScout-1.20.1`, branch `forge-1.20.1`, based on main at 4ee3079) is a port of 0.2.5 to the TerraFirmaGreg Modern 0.13.10 pack's platform (Forge 47.4.13, TFC 3.2.25). Build with JDK 17: `gradlew test build`; libs in `libs/` (`TerraFirmaCraft-Forge-1.20.1-3.2.25.jar`, `Patchouli-1.20.1-85-FORGE.jar` plus a copy named `Patchouli-1.20.1-85-FORGE-1.jar` for flatDir) are not in Git. Version 0.2.5, jar `terrafirmascout-1.20.1-0.2.5.jar`. `gradlew jar -PwithHarness=true` builds a separate `-harness` jar that keeps the dev smoke tests; release jars never contain them.

**Final jar:** `build/libs/terrafirmascout-1.20.1-0.2.5.jar`, 200,696 bytes, SHA-256 18411819859a5e09be0e376f6790516843c8610bacdffdc6e7f67802a35042d3, no development classes. Copied to the user's Downloads. Branch pushed to GitHub as origin/forge-1.20.1 (commits ba12636 and 979250d, README states the tested compatibility). Published as the GitHub prerelease v0.2.5-1.20.1 (jar digest verified against the uploaded asset); not installed in any launcher.

What changed from the 1.21.1 source:
- Build: ForgeGradle 6 + MixinGradle, `mods.toml`, `pack.mcmeta`, and `"refmap"` in the mixin config (without it a real install cannot find Scout's vanilla-class hooks). Java 17 (no `getFirst`/`getLast`).
- TFC 3.2 API: no `Seed` class (the generator seeds from one `XoroshiroRandomSource`: region generator, chunk-data seed, biome-layer seed, same order as `TFCChunkGenerator.initRandomState`); `ChunkData.getAverageTemp/getRainfall`; temperature via `OverworldClimateModel.getAdjustedAverageTempByElevation`; veins via `getVeinsAtChunk(..., biomeFunction)`; `ClimatePlacement.isValid`; heating recipes without `RecipeHolder`; forest types are only none/sparse/edge/normal/old growth, so tree cover 0-4 is the type's position (`TfcCompat.density`); `Region.Point` has no barrier-island/volcanic flags (volcanic comes from the biome). The natural spawn algorithm is identical to 4.x.
- Minecraft 1.20.1 differences: screens must call `renderBackground` (1.21 did it in `Screen.render`; without it screens draw over the previous frame), `mouseScrolled` has three arguments, toast ids, DFU `getOrThrow(false, ...)`, `ServerLevel`/`MinecraftServer` constructors.
- Production-only bugs found and fixed by launching a real Forge client (the dev environment cannot show them): missing mixin refmap reference; `ScoutGenerationExecutor` must be remapped (it targets inherited vanilla methods); the vein-query proxy matched development method names (now also the obfuscated ones); harness reflection by vanilla field name.

World-data-driven resources (generic, work in any pack, identical results in plain TFC):
- `tfc/VeinCatalog.java`: learns the ore veins a world can really generate. A vein counts only when a placed feature for it is listed by a biome that the world's own biome source can produce (so TFC veins a pack disabled, and veins for other planets, are ignored), and what a vein provides is read from the blocks it places (by words in the block name: copper/malachite/tetrahedrite, cassiterite/tin, graphite, hematite/limonite/magnetite/goethite/iron, coal/lignite/bituminous/anthracite; kaolin discs by feature type). Confirmation of a resource accepts exactly those ore blocks (TFC's `tfc:ore/...` or a pack's, for example `gtceu:andesite_tin_ore`).
- `tfc/ResourceAvailability.java` + `SearchWorldContext.adapt`: a resource the world cannot generate is not required, with a notice on the search screen and a log line (`Scout: not requiring [...]`); the skipped set is stored in the profile (`ScoutProfile.skipped`) and in saved results, and old saved results without it still load. Loose copper is skipped when no copper-vein indicator block melts into copper under the loaded recipes.
- New resources Iron and Coal (`Criterion.IRON/COAL`, weight 0, default distances per preset, selectable in the wishlist). They are not in the presets of plain TFC.

TerraFirmaGreg-only behavior (inert unless `su.terrafirmagreg.core` is installed; found by name in `tfc/TfgBridge.java`, no dependency):
- TFG-Core replaces TFC's overworld generation (`new_ow_wg` mixins, `TFGLayers`) and reads one global `Seed.worldSeed` while it generates. The adapter uses TFG's biome layers when `useTfgOverworldPipeline()` is true, sets the global seed only while an adapter builds its region generator, and a scratch world holds an exclusive lock for its whole lifetime so the seed cannot change while it generates (adapter creation therefore waits while a scratch world is verifying, which slows searches).
- TFG presets (Dream, Easy, Fair) also require iron and coal, because TFG's progression needs them soon after bronze. This is the only preset change and only applies with TFG; the log says `Scout: TerraFirmaGreg-Core detected; using its world generation and also requiring [IRON, COAL]`. Basis: TFG's field guide and 0.12.0 changelog (early ores in small veins just below the surface, deeper large veins without indicators, expanded river deposits, bronze to steel progression). Community discussion (Reddit/Discord) could not be retrieved, so no player-survey claims are made.
- In TFG (0.13.10, Core 0.9.23) the pack removes TFC's default veins and adds its own TFC-style veins that place GregTech ore blocks (copper, tin, graphite, iron, coal all present), and removes TFC's ore melting recipes, so loose copper is skipped there. Kaolin stays available.

Tests that actually ran for this branch (final jar contents, same sources): 41 JUnit tests passed (20 + 7 + 14); production-style launches (real Forge 47.4.18 from Prism's cached libraries, private folders `work/port1201/prodtfc` and `prodfull`, launcher script `work/port1201/prod/launch.js`) passed the whole smoke suite with plain TFC + Patchouli and with the FULL TerraFirmaGreg Modern 0.13.10 pack (262 jar mods downloaded at the manifest's exact versions into `work/port1201/fullpack`, pack overrides extracted into `prodfull/game`): adapter equals real chunk climate, repeated feature-stage hash equal, UI button flow, Pause/Stop (TFG worst pause 1.9-4 s and stop 0.7 s while a seed is being checked; plain TFC about 0.2 s), stop after N matches/minutes, layout checks at four sizes, pickers (109 TFG biomes of 264 registered, no vanilla; 30 of 94 in plain TFC), five timed preset searches. Diagnostic (`SCOUT_DIAG=1` harness): in TFG 3 of 6 random seeds confirmed spawn, freshwater, climate, forest, clay, copper, tin, flux, iron and coal. A wishlist search in TFG with the unmodified TFC vein logic found 0 matches in 15 minutes, which is what the vein catalog fixed. The release jar itself was not launched; it differs from the tested harness jar only by the three excluded development classes.

Not tested / limits: dedicated servers; any TFG pack version other than 0.13.10 with Core 0.9.23 (TFG's pipeline selection and `Seed.worldSeed` are internal details that can change); other packs that change world generation (the harness's "adapter equals real chunk" check is not a runtime safeguard); GregTech bedrock fluids (oil), river panning deposits and GT-only ores that are not TFC-style veins are not Scout criteria; slow hardware. A TFG search is much slower than plain TFC (each scratch world also reloads KubeJS server scripts, generation is heavier, and the seed lock serializes adapters with verification).
